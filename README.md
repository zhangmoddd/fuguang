# 浮光

> 轻量 Windows 桌面悬浮工具箱 —— 一个 1.3 MB 的安装包，解决电脑上那些反复做的琐事。
> 全局热键 `Ctrl+Shift+Space` 随时唤出，不占任务栏、不抢焦点。

浮光常驻在屏幕边缘，是一个可以拖动、可以吸附的小球。
左键点开主面板，右键弹出快捷菜单。所有功能都收在这个面板里，不用去任务栏找图标。
**小球的位置会被记住**，拖到顺手的地方之后，下次开机还在那儿。

**设计取向：小、快、不打扰。** 不做内嵌窗口、不做后台常驻服务、不写注册表。
整个软件就是一个 exe 加一个 JSON 数据文件夹。

## 现在能用了什么

五个页签：**文本 / 计时 / 备忘 / 链接 / 设置**。
面板里按 `Ctrl+K` 可以**跨全部四类数据搜索**，不用先想起来东西记在哪个页签。

### 全局搜索（`Ctrl+K`）

四个页签是互相独立的，于是"我记得记过、但想不起来记在哪"成了最大的摩擦。
`Ctrl+K` 把它们放在一起搜，并且**回车直接执行主操作**：

| 搜到的是 | 回车做什么 |
|---|---|
| 文本片段 | **粘贴到光标处**（和列表里点「粘贴」完全一样） |
| 快捷链接 | 在外部打开 |
| 备忘录 | 切到备忘页 |
| 计时器 | 切到计时页 |

- **打分**：标题 / 名字命中永远排在正文命中前面——用户记得住的通常是自己起的名字。
  词首命中额外加成（搜 `git` 时 `github` 排在 `digital` 前面）。
- **多个词**：空格分开，**必须全部命中**（顺序不限）。所以「github 账号」能收敛到
  那一条，而不是把含 `github` 的十条全倒出来。
- **键盘全程可用**：`↑` `↓` 选择、`Enter` 执行、`Esc` 关闭，两端循环。
- **敏感片段在搜索结果里同样遮罩**。不遮的话 `Ctrl+K` 就成了绕过列表遮罩的后门，
  而那个遮罩存在的意义就是防录屏和防旁人扫一眼。
- 打开时**重新读一次数据**，不缓存：缓存会让搜索给出已经删掉的条目，
  那种"点了没反应"最难排查。

### 文本片段

日常在电脑上反复输入的文本、账号、地址、格式模板，收进浮光，一点就粘贴。

- **粘贴到光标处**：点「粘贴」，文字直接出现在你刚才光标所在的位置。
  浮光会记住你上一次真正在用的窗口，粘贴前把焦点还回去，
  所以 Ctrl+V 落在正确的地方，而不是打在浮光自己身上。
- **搜索**：一个搜索框同时匹配标题、正文、备注、标签。
  备注存在的意义就是"以后想不起来这条是干什么的"时还能搜到。
- **敏感内容遮罩**：标记为敏感的条目在列表里显示成圆点，鼠标点一下才展开，
  防止录屏或旁人扫一眼就看到。
- **粘贴后面板不关**：可以连着粘好几条，适合连续填表、连续登录多个账号。
- **收藏与常用排序**：收藏的排最前面，其次是用得最多的。
- **文件夹分类**：像资源管理器那样一层层往里走（面包屑），可嵌套、可改名、可写备注。
  条目用「移动到…」在文件夹之间归类。

> ⚠️ **说清楚一个体验细节**：面板打开时**会取得焦点**，
> 所以那期间你原来程序里的光标会看不见（焦点回到目标程序时又出现）。
> 文字插入的位置不受影响，因为 Windows 会记住每个窗口的光标位置。
> 要做到「面板不抢焦点、光标全程不消失」需要不抢焦点窗口
> （`WS_EX_NOACTIVATE`），但它和「按钮点击可靠」在 Windows 上存在冲突，
> 已列入[已知限制](#已知限制)，安排在后续版本专门设计。

### 计时器

倒计时、番茄钟、秒表三种模式混在一个列表里，每条都能起名字（"煮蛋""开会"）。

- **倒计时存的是绝对结束时刻**，不是剩余秒数。
  所以你设了个 30 分钟倒计时然后关掉电脑去干别的，一小时后开机，
  浮光会直接告诉你"煮蛋已完成"，而不是从 30 分钟重新开始。
- **番茄钟**专注与休息自动循环，阶段切换由 Rust 后台完成 ——
  隐藏的窗口里 JS 定时器会被系统降频，靠它计时会越来越慢。
- **秒表**支持计次。
- 到点时弹出置顶提醒窗 + 提示音，**不抢你当前的焦点**。
- **文件夹分类**：和文本片段同一套（面包屑下钻、可嵌套、可改名备注）。

### 备忘录

按日期归集的日记式：选一天，只看那天的笔记。

- **「记录日期」和「提醒时间」是两个独立字段**，这是这个功能最容易被误解的地方。
  你可以在今天（9 月 19 日）写一条"9 月 25 日交材料"：
  它留在 9 月 19 日那一页（将来回顾时你知道这事是什么时候想起来的），
  但到 9 月 25 日才提醒你。
- 提醒支持**不重复 / 每天 / 每周 / 每月 / 工作日**。
- **错过的提醒不会丢**：开机后浮光会汇总弹一条"你错过了 N 条提醒"，
  而不是开机时噼里啪啦弹八个窗。
- 备忘**不做文件夹**：它的组织维度是日期，再叠一层分类只会让"今天记了什么"变难找。
  它只支持下面的列表密度缩放。

### 快捷链接

把常用的软件、文件夹、文档、网址集中到一处，点一下就打开。

- **纯启动器**：点了就在外部打开，**绝不把外部程序窗口嵌进面板** ——
  那是臃肿和一堆兼容问题的来源。
- **自动提取真实图标**：从 exe 里把图标抠出来显示，提取失败才退回内置图标。
- 添加方式：文件选择框、**直接把文件拖进面板**、手动填网址。
  网址只打 `example.com` 会自动补成 `https://`。
- **文件夹分类**：和文本片段同一套。图标格子会跟着缩放档位一起变大变小。
- **图标大小可调**：在这页按 `Ctrl` + 滚轮，一行放几个图标随手调。
- **自定义启动参数**：悬停格子 → 终端图标，填 `--profile work` 这类参数。
  只对程序和文件有意义，所以网址不显示这个按钮。

### 文件夹与缩放

链接、文本片段、计时器三个页签共用一套**文件夹**：

- **面包屑下钻**：一屏只显示当前层，顶部一条路径（`全部 › 工作 › 项目`），
  点路径里任意一级就能回去。面板只有 420px 宽，左侧树至少要占 140px，
  内容区会被压到没法用，所以没做树。
- **可嵌套**：文件夹里可以放文件夹，层数不限。
- **可改名、可写备注**：备注就是"以后想不起来这个文件夹是干什么的"时看的东西。
- **条目归类**：把条目**拖到文件夹卡片上**，或者用条目上的「移动到…」按钮。
  拖拽只能往下钻（放进当前这一层里的子文件夹），想挪到顶层要用「移动到…」。
  新建的条目自动落在当前那一层。
- **拖拽排序**：链接页可以拖动格子调整顺序，文件夹可以拖动调整**同级**顺序
  （拖到另一个文件夹卡片的上半/下半就插到它前面/后面）。
  文本片段和计时器**刻意不提供手动排序**：它们的顺序是自动算的
  （片段按收藏 → 使用次数 → 最近更新，计时器把运行中的排最前），
  钉一个手动位置会和那套语义打架——而且片段想置顶有「收藏」这个正经入口。
- **删除不级联**：删掉文件夹时里面的内容会移到上一级，并弹原生确认框。

四个页签都支持 **`Ctrl` + 滚轮缩放**，每个页签的档位独立记忆：

| 页签 | 缩放的对象 |
|---|---|
| 链接 | 图标格子尺寸（一行放几个、图标多大） |
| 文本 / 计时 / 备忘 | 列表项密度（行距与内边距） |

> 缩放**不动字号**。字号是设置页里那个独立的「界面字号」，
> 两套东西混在一起，用户就永远说不清"我到底调的是哪个"。
> 普通滚轮仍然是滚动列表——只有按住 `Ctrl` 才缩放。

### 设置

- **全局热键**（默认 `Ctrl+Shift+Space`）：点一下录制框，直接按下你想用的组合键即可。
  如果组合键被别的程序占了，会明确告诉你"注册失败"而不是假装成功。
- **开机自启**（默认关）：写当前用户的注册表启动项，
  你可以在「任务管理器 → 启动」里看到并关掉。
- 提醒提示音开关、剪贴板还原延时、面板是否置顶、数据文件夹位置。
- **界面字号**（四档）与**悬浮球配色**（七套）：两者都是"所见即所得"，
  点一下立刻变，不用等保存。

**界面**：浅色主题，白底配深灰正文（不用纯黑，久看不涩）。
所有文字与背景的对比度都按 WCAG 公式实算校准过，11 组检查全部达标。

## 怎么用

### 直接下载（普通用户）

到 [Releases](../../releases) 下载 `浮光_x.x.x_x64-setup.exe`，双击安装。
安装完从开始菜单或桌面启动，屏幕右侧会出现一个蓝色小球。

不需要安装 Node.js、不需要 Rust、不需要 WebView2 运行库
（Windows 10/11 自带）。

### 从源码运行（想改代码的人）

需要 **Node.js 22.12+** 和 **Rust 1.77.2+**。

> 这两个下限都不是拍脑袋写的，是依赖树实际要求的：
> - `vitest` 5.0.2 的 `engines` 是 `^22.12.0 || ^24.0.0 || >=26.0.0`。
>   用 Node 18/20 时 `npm install` 只警告不报错，`npm test` 却跑在官方不支持的运行时上；
>   而 `1-开发模式.bat`（只走 vite，vite 6 支持 Node 18）看起来一切正常 —— 最容易误判。
> - `tauri` 2.11.6 / `tauri-build` / `tauri-utils` / `tauri-macros` / `tauri-codegen`
>   的 `rust-version` 都是 `1.77.2`。按 1.77.0 装会直接编译失败，而且报错指向依赖、不指向本项目。
>
> 另外装完依赖后**别用 `npm install` 去修依赖树**：`tauri build` 会校验
> npm 包与 Rust crate 的 Tauri 主次版本是否一致，不一致会直接失败。
> 遇到版本相关报错时用 `npm ci`（严格按 `package-lock.json` 装）。

```bash
git clone <仓库地址>
cd 浮光
npm install
npm run desktop:dev
```

Windows 用户可以直接双击仓库里的 bat 脚本，不用敲命令：

| 脚本 | 用途 |
|---|---|
| `1-开发模式.bat` | **日常用这个。** 跑真正的桌面程序，改前端代码存盘即生效，不用编译 exe |
| `2-重新编译.bat` | 要发给别人、或想跑正式版时才用。产物在 `src-tauri/target/release/fuguang.exe` |
| `3-直接启动.bat` | 秒启动上一次编译好的正式版 exe |
| `4-清理编译缓存.bat` | 清理 `target\` 编译残留（实测 6.6 GB）。硬盘紧张时用 |

> 这 4 个脚本的**界面文字是英文**，而且文件刻意写成「纯 ASCII + CRLF 换行」。
> 原因见下方[踩过的坑](#踩过的坑)第 9 条——用中文 + LF 换行会让它们直接失效。
> 每个脚本的用途本表已经用中文说明，所以不影响使用。
> **用编辑器改这些文件时，请务必保存为 CRLF 且不要引入非 ASCII 字符。**

> **关于「每次改都要编译 exe 很烦」**：不用。`1-开发模式.bat` 走的是 Tauri 的 dev 模式，
> 它运行的是真窗口真程序，但前端改动是热更新的。只有 Rust 代码改了才会触发增量编译，
> 通常几秒到几十秒。

## 操作方式

| 操作 | 效果 |
|---|---|
| **按 `Ctrl+Shift+Space`** | **展开 / 收起主面板（可在设置页改，全局生效）** |
| **面板里按 `Ctrl+K`** | **打开全局搜索（跨四个页签）**，`↑` `↓` 选、`Enter` 执行、`Esc` 关闭 |
| 左键点小球 | 展开 / 收起主面板 |
| 右键点小球 | 弹出快捷菜单（打开面板、数据文件夹、隐藏小球、退出） |
| 按住小球拖动 | 移动位置 |
| 面板里按 `Esc` | 收起面板（日历、文件夹弹层打开时只关那一层） |
| 面板里按 `1`~`9` | 快速切换页签 |
| 面板里按 `Ctrl` + 滚轮 | 缩放当前页签的图标 / 列表密度（各页签独立记忆） |
| 左键点托盘图标 | 展开 / 收起主面板 |
| 右键点托盘图标 | 完整菜单（含退出） |

## 数据存在哪

```
%APPDATA%\浮光\
├── snippets.json     文本片段
├── timers.json       计时器（含倒计时的设定时长、番茄钟轮数）
├── memos.json        备忘录（含下一次提醒的绝对时刻）
├── links.json        快捷链接
├── folders.json      文件夹（链接 / 文本片段 / 计时器共用，靠 feature 字段区分归属）
├── window.json       窗口几何（悬浮球上次被拖到的位置）
└── settings.json     设置
```

**每个集合一个文件**，而不是全部塞进一个大 JSON：
好处是写坏一个不会连累其他，你也能单独备份或删掉某一类数据。

**为什么放这里而不是 exe 旁边**：因为你要把它发给别人用，而别人可能把 exe 放在
`C:\Program Files\` 这种只读目录里，放在旁边会直接写入失败。
`%APPDATA%` 是 Windows 给软件存个人数据的标准位置，永远可写，升级也不会丢。

**都是纯文本 JSON**，你可以直接用记事本打开看、手动改、拷走备份。
数据文件损坏时浮光会自动把它备份成 `xxx.corrupt-<时间戳>.json` 再以空数据启动，
不会让你连软件都打不开。

想快速找到这个文件夹：右键点小球 → 打开数据文件夹。

**备份与恢复**：设置页 →「数据」里有「导出 / 恢复」两个按钮。
导出会把**全部数据**（文本片段、计时器、备忘、链接、文件夹、设置）打成一个
JSON 文件放到你挑的位置；恢复时选中那个文件、确认一次，就会覆盖当前全部数据。

- 备份文件带一个格式版本号。**来自更新版本的备份会被明确拒绝**，
  而不是硬导进来把不认识的字段悄悄丢掉。
- 导入的顺序是「六份数据全部写盘成功，最后才更新内存」。
  中途失败时磁盘上最多是新旧混杂，但界面里仍然是导入前那套完整数据。
- 导入完成后面板会整页重载：四个功能模块的内存状态都是导入前那份，
  不重载就会显示已经不存在的数据。
- 为什么是 JSON 而不是 zip：打包压缩要引压缩库，而浮光对发布体积很敏感
  （每个依赖都直接进 exe）。全量数据本来就是几份纯文本 JSON，拼成一个文件够用，
  而且你能**直接用记事本打开检查**——"备份文件看不懂"本身就是一种不放心。

> ⚠️ **数据没有加密。** 敏感内容只有"列表遮罩"这一层视觉保护，JSON 里是明文。
> 这是刻意的取舍：加密意味着你一旦忘记密码，数据就永久找不回来了。
> 请自行评估是否要把真正重要的密码放进来。

## 技术栈与体积

| 项目 | 值 |
|---|---|
| 框架 | Tauri 2 + React 18 + TypeScript + Vite |
| **单文件 exe** | **3.78 MB**（实测） |
| **NSIS 安装包** | **1.33 MB**（实测，压缩后，这是用户实际下载的东西） |
| 安装后占用 | 约 5.7 MB（exe + 开始菜单快捷方式；WebView2 由系统提供，不重复打包） |
| 数据占用 | 1000 条文本片段约 300 KB |
| 内存占用 | 正式版约 22 MB，开发模式约 45 MB |
| 前端产物 | JS 231 KB / gzip 70 KB，CSS 20 KB / gzip 4 KB |

> 以上体积与内存都是**实测值**，不是估算。
> 曾经这里写的是"约 9 MB"，那是从同类项目抄来的数字、没有验证过；
> 实测后发现单文件 exe 只有 3.78 MB、安装包只有 1.33 MB，已更正。

体积能压到这么小，靠的是 `Cargo.toml` 里这几项（都只影响发布构建，不影响开发时的增量编译速度）：

```toml
[profile.release]
opt-level = "s"   # 优先优化体积而不是速度
lto = true        # 跨 crate 内联与死代码消除
codegen-units = 1 # 让 LTO 能看到全部代码
panic = "abort"   # 去掉 unwind 表
strip = true      # 剥掉符号
```

对照：同一份代码的 debug 构建是 **15.17 MB**。

编译缓存 `src-tauri/target/` 已被 `.gitignore` 排除，不进仓库、不随发布分发。
想回收磁盘双击 `4-清理编译缓存.bat`，代价是下次编译变慢
（release 全量编译实测 10 分钟）。

## 项目结构

```
浮光/
├── src/                          前端
│   ├── features/                 每个功能一个文件夹，自带 CSS
│   │   ├── registry.ts           ★ 功能模块注册表
│   │   ├── snippets/             文本片段
│   │   ├── timer/                计时器（倒计时 / 番茄钟 / 秒表）
│   │   ├── memo/                 备忘录（日记式 + 定时提醒）
│   │   │   └── Calendar.tsx      ★ 自绘日期选择器（原生 date 弹层控制不了位置和大小）
│   │   ├── links/                快捷链接（启动器）
│   │   └── settings/             设置
│   ├── lib/
│   │   ├── api.ts                ★ 与 Rust 通信的唯一入口
```

### 怎么加一个新功能

这是浮光刻意留的扩展点。加功能**不需要改动主面板的代码**：

1. 新建 `src/features/你的功能/index.tsx` 和同目录的 `你的功能.css`
2. 导出一个 `FeatureModule`（见 `src/features/registry.ts` 的类型定义），在文件里 `import "./你的功能.css"`
3. 在 `registry.ts` 的 `FEATURES` 数组里加一行

页签、图标、排序、快捷键 `1`~`9` 全部自动生效。页签栏放不下时会横向滚动。

### 计时和提醒为什么不放在前端

面板窗口平时是隐藏的，而**隐藏的 WebView 里 `setInterval` 会被系统降频** ——
靠它计时，倒计时会越走越慢、提醒会漏。

所以权威时钟在 Rust 的 `scheduler.rs` 里（每 500ms 检查一次），
前端只负责显示和编辑。

但**日期计算全部在前端**：`Date` 原生按本地时区工作、夏令时也正确，
而 Rust 标准库没有日历能力。所以分工是「前端算下一次是什么时候，Rust 到点弹窗」。

### 粘贴到光标处是怎么实现的

这是浮光技术上最核心、也最容易出问题的一环，完整逻辑在
[`src-tauri/src/platform.rs`](src-tauri/src/platform.rs)：

1. 后台线程每 400 ms 记录一次当前前台窗口（跳过浮光自己的三个窗口），
   所以浮光始终知道"用户上一次真正在用的窗口"是哪个。
2. 点击「粘贴」时：先备份用户当前剪贴板 → 写入要粘贴的文本
   → 用 `AttachThreadInput` + `SetForegroundWindow` 把焦点还给目标窗口
   → 模拟 `Ctrl+V` → 等 120 ms → 把原剪贴板还回去。
3. 如果找不到目标窗口（例如用户刚关掉了那个程序），
   内容会留在剪贴板里，并明确提示"请手动 Ctrl+V"，不会静默失败。

## 已知限制

- **面板打开时会取得焦点**，所以你原来程序里的光标会暂时看不见
  （粘贴那一刻焦点会还回去，插入位置不受影响）。
  要做到光标全程不消失，需要把面板做成不抢焦点窗口（`WS_EX_NOACTIVATE`），
  但 Windows 上不抢焦点的窗口其按钮点击行为会变得不可靠
  ——「不抢焦点」和「按钮好点」天生冲突，需要专门设计交互，安排在后续版本。
- **极少数程序**（部分密码输入框）会因为剪贴板被临时替换而行为异常。
  遇到时用「复制」按钮手动粘贴。
- **数据未加密**。敏感内容只有列表遮罩这一层视觉保护，JSON 里是明文。
  这是刻意的取舍：加密意味着一旦忘记密码，数据就永久找不回来了。
  请自行评估是否要把真正重要的密码放进来。
- **拖入目录现在能认出来了**：前端拿不到文件系统信息，所以由 Rust 读一次属性，
  文件夹不会再被当成「文件」（图标也就对了）。
- **链接暂不支持拖拽排序**，按添加顺序排列。
- **拖拽只能往下钻**：把条目拖到文件夹卡片上是"放进那一层"，想挪回顶层要用「移动到…」。
- **文件夹不能靠拖动改变父子关系**（要嵌套就在那一层里新建），拖动只调整同级顺序。
  否则"落在卡片中间"到底是排到它前面还是放进去，会有歧义。
- **文本片段与计时器不支持手动排序**，它们的顺序是自动算的，理由见上文。
- **拖拽是用指针事件自绘的，不是 HTML5 拖放**：Tauri 在 Windows 上要求关掉窗口的
  `dragDropEnabled`，HTML5 的 `dragstart` / `drop` 才会触发，而那会**同时废掉
  「把文件拖进面板添加链接」**——那是已经在用的功能。两者冲突，
  所以这里自己实现（见 `lib/drag-drop.ts`），顺带也就不和 OS 级的文件拖放打架。
- **备忘不做文件夹**：它的组织维度是日期。
- **多显示器**：面板会跟着小球出现在**同一块屏幕**上（用的是小球所在那块屏幕的
  边界，副屏在主屏左边时也不会被夹回主屏）。小球的位置会被记住，
  重启后回到你上次拖到的地方；如果那块屏幕已经不在了（拔掉副屏、改了排列），
  会退回主屏右侧的默认位置，而不是把小球摆到看不见的地方。
- **开机自启在开发模式下会指向 `target\debug` 的调试版 exe**，
  设置页里有明确提示。正式安装后路径才是安装目录。
- **卸载时那个「删除应用程序数据」删不掉你的数据。** 安装器（Tauri 的 NSIS 模板）
  删的是 identifier 目录 `%APPDATA%\com.fuguang.app`，而浮光的真实数据在
  `%APPDATA%\浮光`（见 `storage.rs` 的 `APP_DIR_NAME`）。所以卸载时勾了它，
  `snippets.json` / `memos.json` 这些**明文**文件仍留在磁盘上。
  想彻底清理请手动删掉 `%APPDATA%\浮光`。
  根治办法是给 `bundle.windows.nsis` 加 `installerHooks` 去改删除路径 ——
  但那必须真装一次再卸一次才能验证，属于「改了却没法证明它对」的改动，故暂缓。
- **番茄钟的专注/休息时长只能新建时设定**，运行中改不了（改需停止后重建）。
- **粘贴时如果剪贴板里是图片/文件（不是文本），那部分内容会被替换且无法还原。**
  浮光的粘贴靠"借剪贴板"实现，只备份得了文本。现在遇到这种情况会明确提示
  「剪贴板里原来的内容不是文本，已被替换，无法还原」，但**不会阻止替换**。
  要真正保住它得把剪贴板里所有格式都复制一份（`EnumClipboardFormats` +
  按格式复制 HGLOBAL / GDI 句柄再逐个写回），是一段不小的 unsafe 代码，
  而且必须在真实交互桌面上验证，故暂缓。

## 对抗式审查的结果

这个项目经过多轮**独立**对抗式审查（审查者与实现者不是同一个人，且每一轮都会重新审
"上一轮的修复本身"）。这里记两件事：**修掉的**，和**查实但明确决定不修的**。
后者必须写清原因 —— 不许静默忽略。

### 已修（摘要）

细节在代码注释与测试里，逐条都有"为什么"和可复现的触发路径。

- **数据安全**：UTF-8 BOM 会让整个数据文件被判损坏并改名（实测丢过一整份设置）；
  读取失败被静默当成"文件不存在"、下次写入即销毁原文；`write_json_at` 的
  "先删后改名"制造了目标不存在的窗口，且临时文件名会撞（时钟粒度 100ns，
  实测连续取值 66% 与前一次相同、8 线程 8 万个名字撞掉 68%）；
  备份导入把"缺这一段"当成"清空这一段"，一次部分备份就能抹掉全部数据；
  备份导出不在写锁内，与导入并发时会导出混合快照
- **并发**：写入都是"锁内改内存、锁外落盘整份数组"，先取快照的写者可能后落盘，
  把新数据整份盖回旧值（已复现：编辑被回滚、删掉的计时器复活）→ 加写锁并强制在锁内重取快照；
  防抖写盘用一个布尔同时表示"有改动"和"正在写盘"，飞行期间的新改动被永久丢弃 → 换成版本号 + 严格串行
- **提醒**：重复提醒的推进写在前端备忘页里，而主面板只挂载当前页签（默认不是备忘），
  不打开备忘页就永不推进、重复提醒永久静默；DST 春季跳变当天的钟点被永久改掉；
  年份 < 100 被 JS 当成 1900+y，且 `dateKey` 不补零导致自己产出的键自己认不出
- **其它**：热键注册失败不回滚旧组合、autostart 句柄泄漏、面板置顶是死设置、
  提醒音开关不生效、图标提取自动连 UNC 会触发 NTLM 认证、explorer 参数注入、
  剪贴板还原判据恒为假（要求序号差 1，实测一次写入涨 5）、
  autostart 会误删"带参数/未加引号含空格"的能正常工作的自启项、
  `capabilities` 从 15 项收到 5 项（删掉的 10 项里：5 项前端零调用、4 项本来就含在
  `core:default` 展开出的 `core:window:default` / `core:webview:default` 里、
  1 项 `opener:default` 只被 Rust 自由函数调用不经 ACL。注意 `scale_factor` 与
  `internal_toggle_devtools` **仍在被使用**，只是靠 `core:default` 兜底 ——
  所以删的是"冗余的显式声明"，不是"冗余的能力"）

### 已知风险（明确决定暂不修）

这几条都是对抗式审查查实的问题，不是遗漏。写在这里是为了**不静默忽略**。

- **`reveal_path` / `open_target` 两个命令没有接线**：`lib.rs` 注册了、
  `api.ts` 声明了，但没有任何组件调用。它们目前只对"已经能自己 invoke 的
  失陷前端"可用，等于半接线状态。要么接上（`reveal_in_explorer` 现在会拒绝
  含 `"` 的路径），要么删掉。
- **`autostart::is_enabled` 与 `set_enabled(false)` 语义不对称**：
  `is_enabled` 只认指向当前 exe 的记录，而关闭时不校验路径、无条件删值。
  刻意保留：用户可能被一条写坏的启动项困住，**关闭必须永远可用**，
  否则连自救都做不到。设置页只在路径匹配时才显示"已开启"，所以从界面走不到这个不对称。
- **`scheduler` 线程没有 panic 守卫**：`start()` 用裸 `thread::spawn`，
  没有 `catch_unwind`，线程一旦 panic，`loop` 直接结束、`JoinHandle` 被丢弃 ——
  **所有提醒会永久静默**，而且没有任何地方能发现（重启才恢复）。
  目前没有已知的 panic 路径（`focus_minutes` / `break_minutes` 为 0 那条
  已经在 `evaluate` 里用 `.max(1)` 兜住了，见 `番茄钟时长为零也不会变成弹窗风暴`），
  所以这是防御性缺口而不是已知故障，故暂缓。
- **拖拽过程中滚动列表，落点会算错**：候选矩形在越过阈值那一刻只采集一次
  （`drag-drop.ts` 的 `s.collect()`，注释说明是刻意的——每帧对所有卡片调
  `getBoundingClientRect` 会强制同步布局）。而落点判定用的是**当前**视口坐标，
  两者在滚动后就对不上了，表现为"松手插到了别处"。
  修法要么每帧重采（有性能代价），要么监听滚动容器重新采集（要引入依赖），
  属需要权衡的改动，故暂缓。

> 审查里还报过两条，核对后**不成立**，一并记下来免得下次重复怀疑：
> 「把链接拖进文件夹会顺手点开那个文件夹」——`click` 的派发目标是
> mousedown 与 mouseup 的**最近公共祖先**，从链接卡片拖到文件夹卡片上松手时
> 公共祖先是网格容器，文件夹的 `onClick` 根本不会触发。
> 「按住拖出窗口后松手，pointerup 会丢」——按住按键期间浏览器有**隐式指针捕获**，
> 事件仍然会送达。

还有几条是**窄窗口竞态 / 产品取舍**，评估后决定不动：

- **`reload()` 会整表覆盖本地状态**（链接页与计时器页都是）。如果一次 IPC 往返
  期间用户刚做了改动，回读结果会把界面刷回旧值。**磁盘不受影响**——每条改动
  都是单独 `*_save` 上去的，所以后果只是"界面短暂显示旧值"，下一次刷新就自愈。
  修法要给每个页签加"本地版本号"，改动面比收益大，故暂缓。
- **提醒内容在"窗口刚建好、前端还没挂载"时会丢**：复用提醒窗时 Rust 走
  `emit("alert:content")`，若此刻监听器还没注册，事件被丢弃；而调度线程
  **已经**把 `fired_for` 落盘了，那条提醒就再也不会补弹。触发条件是两条提醒
  落在同一次 WebView2 冷启动窗口内（首条走 URL query 兜底，是安全的）。
  真正的修法是让前端挂载时**主动拉一次**当前提醒内容（加一个 `alert_current` 命令），
  而不是只依赖事件推送。
- **早上 9 点前给"过去某天"的备忘勾提醒，保存后会立刻弹窗**：默认值是
  "那天 09:00"，而 `firstOccurrence` 对不重复的提醒会**原样返回过去时刻**。
  这是刻意的取舍（"设在过去就立刻提醒"好过"永远不提醒"），要改属于产品决策，故保留。
- **把提醒日期正好选在夏令时跳变那一小时（例如美东 3-08 的 02:30），钟点会从
  第一次起就落在 03:30。** `atLocalTime` 防住的是**推进**路径（不让归一化结果
  变成新基准），但**创建**路径走的是 `combineLocal`，那里本地 02:30 不存在、
  被引擎归一化成 03:30 并直接存进 `remindAt`，之后每次推进都从它取钟点。
  触发面很窄（要同时命中跳变日和跳变小时），且"该跳过那天还是该晚一小时"是产品决策，
  故暂缓。
- **`hotkey::apply` 超时后那条请求仍留在待处理队列里**：用户下次换键时
  `process_requests` 会把陈旧请求一并执行，中间一瞬热键是用户以为已经放弃的组合。
  修法是给请求加序号、超时后从队列里摘掉自己 —— 但 `process_requests` 的
  `mem::take` 与摘除之间仍有微秒级窗口，关不干净，而可达性极低（要热键线程卡满 3 秒），
  风险大于收益，故暂缓。
- **在「任务管理器 → 启动」里禁用过的自启项，设置页会显示"已开启"**：
  Windows 那里不是删 Run 值，而是往
  `HKCU\…\Explorer\StartupApproved\Run\浮光` 写一个 12 字节 blob
  （首字节 `0x02` = 启用、`0x03` = 禁用）。`is_enabled()` 只看 Run 值，
  于是显示"已开启"但开机不启动；用户点关再点开，blob 仍是 `0x03`，开关永远修不好。
  **本机已实测 blob 的存在与格式**（18 条，`Ditto => 02`、`Steam => 03`、
  `OneDrive => 03`），但"删掉 Run 值再写回后 Explorer 是否仍按 `0x03` 跳过"
  要注销/重启才能验证 —— 按**未验证**处理，故暂缓。修法是启动时读那个 blob，
  或在设置页显示第三态。
- **剪贴板原本是空的时候，片段内容会永久留在剪贴板里**：那种情况没有东西可还原
  （`backup == None` 且剪贴板本来就空），所以第 5 步什么都不做、也不提示。
  对普通片段无所谓（等于多复制了一次），但带「敏感」标记的片段会因此留在剪贴板里。
  要改属于产品决策（粘完主动清空会破坏"再粘一次"的预期），故保留。
- **命令面板里粘贴片段不累加使用次数**：片段页的 `bumpUse` 会 +1，面板那条路径没有 ——
  而面板恰恰是主推入口（"搜到就粘，不用先切页签"），于是"常用优先"的排序长期失真。
  **没有直接修**是因为 `api.ts` 里没有 `snippet_save`，前端要改就得再开一个
  `usePersistentState("snippets.json")` —— 那会让同一个文件在一个窗口里出现**两个写者**
  （`WriteCoordinator` 是每实例一份），互相覆盖的风险远大于这个排序失真。
  正确的修法是加一个 Rust 侧命令（Rust 持有写锁），留给以后。
- **两条碰真实剪贴板的测试默认不跑**（`cargo test` 会报 `2 ignored`）：它们要覆盖
  用户剪贴板，所以在 CI / 日常跑测试时不执行。想跑用
  `cargo test -- --ignored`（跑完尽量把文本还回去，图片/文件这类还原不了）。
  用 `#[ignore]` 而不是"检测到剪贴板不合适就 `return`"是有意的：`return` 会让测试
  以 `ok` 出现却**一条断言都没跑**（libtest 还会吞掉 stderr），实测真的发生过
  （`105 passed` 里有两条是空的）；`ignored` 在输出里**看得见**。
  真正决定"该不该还原"的逻辑已经拆成 `decide_restore` / `decide_original_lost`
  两个纯函数，由 `收尾决策穷举` 在**任何机器上**都真跑（CI 也一样）。
- **热键注册失败只写进 `app.log`，界面上看不到**：用户按热键没反应时，
  设置页仍然显示"已开启"。启动时会重试 3 次（覆盖"旧实例还没完全退出"这种
  瞬时占用 —— 实测过），但若是**别的程序**长期占着这个组合键，用户只能自己去翻
  `%APPDATA%\浮光\app.log`。正确的修法是让设置页显示**真实**的注册状态
  （`hotkey::CURRENT` 里已经存着"实际注册成功的组合"，加一个查询命令就能接上），
  属于新增 UI，故暂缓。

## 测试

```bash
# Rust：调度判定、存储原子性、数据兼容性、base64
cd src-tauri && cargo test

# 前端：日期推算与格式化
npm test              # 当前时区
npm run test:dst      # 在 America/New_York 下再跑一遍（见下）
npm run test:all      # 两个时区都跑
npm run check         # 类型检查 + 测试
```

### 为什么测这些，而不是测别的

测试只覆盖**"错了也不会立刻被发现"**的部分：

| 测什么 | 不测的话会怎样 |
|---|---|
| `scheduler.rs` 的到点判定与幂等 | 提醒漏弹、或每 500ms 重复弹一次刷屏 |
| 番茄钟阶段切换 | 专注结束不进入休息，番茄钟只跑一轮就停 |
| `storage.rs` 的原子写入与损坏恢复 | 断电时数据文件被写成半截，用户数据永久丢失 |
| 数据模型的反序列化兼容 | 新版本读不了旧数据文件，用户的计时器一夜消失 |
| `datetime.ts` 的重复规则 | "每月 31 日"跑到 3 月 3 日、工作日提醒落在周末 |
| 手写 base64 编码 | 图标花掉，且前端会静默降级成内置图标，你根本不知道 |

界面外观、布局这类"一眼就能看出问题"的东西没有测 —— 那些靠肉眼看更划算。

### 夏令时测试为什么要换时区

**中国时区没有夏令时。** 如果只在默认时区跑，那些夏令时断言会永远通过，
等于没测。所以 `datetime.test.ts` 里的夏令时断言用 `describe.skipIf` 守卫，
只在当前时区确实有夏令时时执行；`npm run test:dst` 会换到 `America/New_York`
把它们真正跑起来。

这不是理论担忧，实测过：

| 实现 | 中国时区 | 纽约时区 |
|---|---|---|
| 正确（改日期后重设时分） | ✅ 通过 | ✅ 通过 |
| 错误（直接 `+ 86400000` 毫秒） | ✅ **通过（抓不到）** | ❌ 抓到 3 个失败 |

也就是说，**没有这个换时区的机制，夏令时的 bug 会完全逃过测试**。

### 测试要能失败才有意义

写完测试后做过变异测试：故意破坏几处逻辑，确认测试真的会红。
结果都被抓到了：

| 故意引入的 bug | 被哪条测试抓到 |
|---|---|
| 去掉备忘的幂等判断 | `备忘提醒不会重复弹` |
| 倒计时结束后不清 `ends_at` | `倒计时到点触发并标记完成` |
| 番茄钟不重设 `ends_at` | 番茄钟的两条阶段切换测试 |
| "每天"规则改成 `+86400000` | 纽约时区下的 3 条夏令时测试 |
| `firstOccurrence` 循环上限太小 | `多年前的陈旧提醒也能跳到未来` |

> 💡 **做变异测试时的坑**：如果用"拷贝文件 → 改 → 测试 → 拷回来"的方式，
> `Copy-Item` 会**保留原文件的修改时间**，还原后文件比编译产物还旧，
> cargo 会认为"没变化"而继续复用变异版本的缓存。
> 表现为"明明还原了，测试还是红的"。解法是还原后手动刷新文件 mtime。

## 发布流程

### 本地验证打包

```bash
npm run desktop:build
```

产物：

| 文件 | 说明 |
|---|---|
| `src-tauri/target/release/fuguang.exe` | 单文件绿色版，可直接运行 |
| `src-tauri/target/release/bundle/nsis/*.exe` | NSIS 安装包，发给普通用户 |

### 自动出包

仓库里有两个 GitHub Actions 工作流：

| 工作流 | 触发时机 | 做什么 |
|---|---|---|
| `.github/workflows/ci.yml` | 每次 push 与 PR | 类型检查、两个时区跑前端测试、Rust 测试、编译检查 |
| `.github/workflows/release.yml` | 打 `v*` tag，或手动触发 | 跑全部测试 → 构建安装包 → 创建 Release（草稿） |

发一个版本：

```bash
# 1. 改版本号（三处要一致）
#    package.json / src-tauri/Cargo.toml / src-tauri/tauri.conf.json
#    改完先跑一次自检，它会同时校验「三处一致」和「tag 与版本号相符」：
node scripts/check-version.mjs v0.2.0
# 2. 更新 CHANGELOG.md
# 3. 提交并打 tag
git commit -am "chore: 发布 v0.2.0"
git tag v0.2.0
git push origin main --tags
```

> 第 1 步那个自检**不是可选的**：安装包的文件名取自 `tauri.conf.json` 的
> `version`，而 Release 标题取自 tag。两者不一致时会静默产出一个
> 「标题 v0.2.0、里面是 0.1.0 安装包」的 Release，而 release 工作流
> 里没有别的步骤能拦住它。现在工作流里也加了这一步。

几点刻意的设计：

- **测试不过就不出包**。release 工作流在构建前会跑全部测试，
  包括换到有夏令时的时区再跑一遍。宁可不出包，也不要把坏版本发出去。
- **Release 默认是草稿**。自动构建出的安装包没人手动试过，
  先发草稿、人工确认能装能跑，再点发布。
- **安装包和裸 exe 都会作为 artifact 上传**，即使 Release 还是草稿也能单独下载来试。

## 踩过的坑

如果你也要做 Tauri 悬浮窗工具，下面几条都是实测踩出来的，能省你几个小时：

1. **同步命令跑在主线程**。Tauri 的 `#[tauri::command] fn`（非 async）在主线程执行，
   而主线程同时跑窗口消息循环。于是：
   - 在同步命令里创建窗口 → Windows 上**死锁**（Webview2 已知问题）
   - 在同步命令里 `menu.popup` → 内部要派发到主线程，等于主线程等自己，**菜单永远不弹**
   凡是碰窗口和菜单的命令，一律标 `async`。

2. **托盘 / 菜单回调也在主线程**。这些回调里创建窗口同样会死锁，
   必须 `std::thread::spawn` 丢出去。

3. **窗口外框不等于内容尺寸**。设了 `inner_size(56, 56)`，实测 `GetWindowRect` 返回 136×56。
   按设定尺寸算坐标会让窗口跑到屏幕外（小球被切掉一角）。
   正确做法是创建后读回真实尺寸再定位。

4. **自绘右键菜单会被小窗口裁掉**。球窗口只有 56×56，菜单画在球下方直接看不见。
   撑大窗口又会用透明区域挡住桌面点击。用系统原生菜单最省事。

5. **原生菜单要求宿主窗口在前台**，否则菜单刚出现就被系统关掉。
   球窗口是 `focused(false)` 的后台窗口，弹出前必须
   `AttachThreadInput` + `SetForegroundWindow` 把它挂到前台。

6. **WebView2 自带的右键菜单会盖住你的菜单**。只在 React 组件上 `onContextMenu`
   里 `preventDefault()` 拦不住，必须在 `document` 上用**捕获阶段**监听。

7. **别手写拖动逻辑**。用 `e.screenX` 算增量再改窗口位置，
   在缩放不为 1 的屏幕上会因逻辑/物理像素换算累积误差，实测把小球甩到屏幕另一头。
   超过阈值后交给 `startDragging()` 让系统处理。

8. **背景别太透**。面板常驻在其他窗口之上，透明度一高，
   桌面上的文字数字就会透过来和内容混在一起，搜索和阅读都很累。

9. **Windows 批处理文件必须是 CRLF 换行，而且内容要保持纯 ASCII。**
   这一条是踩得最惨的：仓库里的 4 个 `.bat` 最初由自动化工具生成，
   写成了 **LF 换行 + UTF-8 中文**，结果双击毫无反应。

   实测四种组合：

   | 组合 | 结果 |
   |---|---|
   | LF + UTF-8 | ❌ 中文乱码成 `[OK] if鎷彿鍧楁`，`if` 块和 `goto` 崩坏，cmd 卡在等待输入 |
   | CRLF + UTF-8 | ⚠️ 控制流恢复，但中文仍全部乱码 |
   | CRLF + UTF-8 带 BOM | ❌ BOM 破坏 `@echo off`，每行命令都被回显 |
   | CRLF + 纯 ASCII | ✅ 完全正常 |

   LF 换行会让 cmd 的括号块解析错位，于是脚本一直等后续输入，
   表现就是「双击没反应」。UTF-8 的中文则救不回来——cmd 按当前代码页
   （中文 Windows 是 GBK）读取批处理文件字节，`chcp 65001` 也来不及。

   所以这 4 个脚本刻意只用英文、纯 ASCII、CRLF。
   中文说明放在本 README 里。**用编辑器改这些文件时，
   请确认保存为 CRLF 且不要引入非 ASCII 字符**，否则会再次踩同一个坑。

10. **Rust：块尾表达式里的 `MutexGuard` 临时变量，析构晚于局部变量。**
    写成这样编译不过：

    ```rust
    let store = app.state::<Store>();
    store.lock().timers.clone()   // 函数尾表达式
    ```

    报错是 `` `store` does not live long enough ``。原因是尾表达式产生的临时值
    （那个 `MutexGuard`）会在**局部变量 `store` 之后**才析构，
    于是借用检查器认为 `store` 被借走时已经被丢弃了。
    解决办法是先绑定再返回：

    ```rust
    let list = store.lock().timers.clone();
    list
    ```

11. **一个真实的设计漏洞：倒计时忘了存"设定时长"。**
    最初 `Timer` 里只有 `remaining_ms`（暂停时的剩余量），
    而到点后它会被清成 0。于是「重置」和「重新开始」没法知道用户当初设了多久，
    只能去猜一个默认值——**重置之后重启软件，25 分钟的倒计时会变成 5 分钟。**

    修法是加一个独立的 `duration_ms` 字段，语义是"用户设了多久"，
    与"这一轮还剩多久"分开。教训是：**凡是用户输入过的配置值，
    都要有自己独立的持久化字段，不要试图从运行时状态里反推。**

12. **`RegisterHotKey` 把热键绑在「调用线程的消息队列」上。**
    这是个很隐蔽的坑：在 Tauri 的异步命令里调 `RegisterHotKey(NULL, ...)`，
    注册会"成功"（返回非 0），但 `WM_HOTKEY` 被投递到那个**不泵消息的工作线程**队列里，
    于是热键永远不触发 —— 而且完全不报错。

    解法是开一个专属线程，让它既负责注册、也负责跑 `GetMessageW` 循环。
    换热键时用 `PostThreadMessageW` 把它从阻塞中唤醒，让它自己去注销与重注册
    （注册和注销必须在同一个线程上完成）。

    另外 `MOD_NOREPEAT` 别忘加：不加的话按住组合键会以键盘重复速率连续触发，
    面板会疯狂开合。

13. **验证热键不需要模拟按键。** `RegisterHotKey` 对同一组合键是全局独占的，
    所以只要在软件运行时用另一个进程去注册同一个组合键，
    拿到 `ERROR_HOTKEY_ALREADY_REGISTERED`（错误码 1409）就说明它确实注册成功了；
    再拿一个没注册过的组合键作对照，确认测试方法本身有效。
    这样可以在**完全不碰用户键盘鼠标**的前提下验证热键功能。

14. **AI 生成的 logo 直接缩到 52px 会糊成一团。**
    这是把一个"大图"当"图标"用时的典型翻车。浮光的标志是一张 AI 生成的图
    （一点光浮在水波上），原始尺寸 1254×1254，但：

    - 图形只占画布的 **39% × 29%**，四周全是黑，必须先按非黑区域裁紧
    - 它是**柔光渲染**，不是扁平矢量；缩到 52px 后光晕变成糊
    - 水波两端收得很尖，缩下去**直接消失**，只剩中间一小段

    解决方法是三步处理，缺一不可：

    1. **把亮度当透明度**抠图（白图黑底天然适合这么做）
    2. 用 gamma 曲线**压掉柔光**，只留主体形状
    3. **按目标尺寸分别做形态学膨胀（加粗）**——
       小尺寸的笔画在缩放中会丢，必须在目标尺寸上补回来，
       不能靠一张大图缩下去。ICO 的七个尺寸各自渲染、各自加粗。

    但加粗有代价：加过头会把四角星内凹的弧线填平，
    火花变成"十字"。实测**加粗一档是甜点**——形状还在，52px 也能看清；
    加粗两档最清楚但形状毁了。这类事情必须**渲染出来比**，
    不能靠"应该能看清吧"来判断。

15. **Windows 控制台的「快速编辑模式」会让构建"假死"。**
    这是最像灵异事件的一个：开发模式启动后卡了十几分钟没有任何输出。

    排查结果很反直觉——`tauri dev` 进程：

    | 指标 | 值 | 含义 |
    |---|---|---|
    | CPU | 0.09 秒 | 完全没在干活 |
    | 子进程 | 无 | 连前端服务器都没启动 |
    | 网络连接 | 无 | 不是在下载依赖 |
    | 端口 4173 | 空闲 | Vite 从未起来 |
    | 线程状态 | 全部 Wait | 在等一个本地资源 |

    真相是：控制台默认开启「快速编辑模式」，本意是让用户能用鼠标选中文字复制。
    但它的实现方式是——**只要在窗口里点一下鼠标就进入选择状态，
    此时任何想往该控制台写输出的进程都会被系统挂起**，
    按回车或 Esc 才解除。

    所以"卡死"其实是编译程序在等你按回车。对动辄几分钟的编译流程来说，
    这个坑必踩——用户总会去点那个窗口。

    **修法**：在启动脚本里清掉 `ENABLE_QUICK_EDIT_MODE`（见
    `tools/console-quiet.ps1`）。两个容易踩的细节：

    - 必须**同时设置** `ENABLE_EXTENDED_FLAGS`（0x0080），
      否则对 `QUICK_EDIT` 的修改会被 Windows 直接忽略——文档要求，不设等于没改
    - 关掉后仍可用右键菜单的「标记」选中文字，所以"复制报错发给别人"的能力没有丢

16. **多窗口应用里，CSS 变量是"每个窗口各一份"的。**
    浮光有三个独立窗口（小球 / 主面板 / 提醒弹窗），各自有各自的 DOM 和
    `documentElement`。所以在设置页里改 CSS 变量，**小球那个窗口完全不知道** ——
    实测就是这个原因导致"换了悬浮球配色但球不变色"。

    改法是把设置变更通过 Tauri 事件广播出去，关心外观的窗口各自重新套用：

    ```ts
    // 设置页保存后
    await api.settingsSave(next);
    await emitSettingsChanged(next);

    // 小球窗口
    onSettingsChanged((s) => applyBallTheme(s.ballTheme));
    ```

    顺带一提：启动时的首次套用要在各窗口的入口（`main.tsx`）里做，
    事件只负责"之后被改动了"的情况 —— 两个路径都要有，缺一个就会出现
    "刚启动时是对的，改了不变"或者反过来。

17. **别把"关闭窗口"的图标绑成"退出进程"。**
    面板标题栏原本有个 ✕，我把它绑成了"退出浮光"。用户按窗口惯例点它想
    收起面板，结果**整个软件被杀掉、悬浮球也一起消失**。

    ✕ 在任何窗口里都意味着"关掉这个窗口"，把它绑成杀进程是危险的错配 ——
    用户越熟练，越容易中招。

    修法：✕ 只收起面板；退出改到设置页底部、小球右键菜单、托盘菜单 ——
    那几处才是用户明确表达"我要退出"的地方。

18. **调试版被设成开机自启，开机后看到的是浏览器的「无法访问此页面」。**
    用户报的现象是"开机弹出悬浮球，球是坏的，点开面板里是没联网的浏览器错误页"，
    听起来像软件坏了或者断网，实际原因在构建类型上。

    Tauri 的 **debug 构建不把前端打包进 exe**：窗口地址是 `tauri.conf.json` 里的
    `devUrl`（`http://127.0.0.1:4173`），也就是 Vite 开发服务器。
    在开发模式里永远看不出问题，因为服务器就在那儿；但 Run 键是在**登录那一刻**
    拉起进程的，那时服务器根本不在，WebView2 拿不到页面 ——
    小球和面板里就都成了浏览器的联网错误页。release 构建才把 `dist/` 内嵌进二进制，
    所以它开机启动不依赖任何外部服务。

    更隐蔽的是**状态显示**：注册表里只有一条 `浮光`，从正式版打开设置页时，
    旧代码只判断"这个值在不在"，于是显示"自启已开启"，
    用户完全不知道开机启动的其实是 `target\debug` 里那个另一个 exe。

    修法是两条，缺一不可：

    - **调试版直接拒绝开启自启**：`set_enabled(true)` 在 `cfg!(debug_assertions)` 时返回错误。
      只在设置页写一行小字提示是挡不住的，用户照样会去勾。
    - **`is_enabled()` 只认指向当前 exe 的记录**，路径比较要按 Windows 的规则来
      （大小写不敏感、正反斜杠等价、忽略结尾分隔符），否则设置页会显示一个
      "看起来对、实际指向别的程序"的状态。

    已经中招的机器要手工清掉 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\浮光`，
    再用正式版 exe 重新开启自启。

19. **编译缓存别留在 D 盘，也别忘了正式版 exe 是绿色单文件。**
    `src-tauri\target\` 实测能长到 6.6 GB，而最终的正式版 exe 只有十几 MB ——
    中间产物比成品大了三个数量级。磁盘紧张时的正确做法不是反复删了重建，
    而是：

    ```powershell
    # 1. 把编译缓存放到空间大的盘（只影响这一次会话，不写进仓库）
    $env:CARGO_TARGET_DIR = 'E:\cargo-target\fuguang'
    npm run desktop:build -- --no-bundle   # --no-bundle 跳过 NSIS 安装包，只要 exe
    ```

    2. 把 `target\release\fuguang.exe` **复制到别处**（例如 `D:\software\浮光\`），
    3. 然后整个 `target\` 可以放心删掉。

    正式版 exe 自带前端、自带全部依赖，不依赖 `node_modules`、`dist` 或开发服务器，
    双击就能跑。**所以"每次都要编译"其实是个误解：编译一次、把 exe 拿出来，
    之后永远不用再编译。** 只有改了源码才需要重新编译。

## 开发约定

- **前端不直接写 `invoke("命令名")`**，一律走 `src/lib/api.ts`，
  这样命令名拼错会在编译期暴露。
- **不引入新依赖要谨慎**：每加一个前端库都会直接进最终的 exe 体积。
  提示音用 WebAudio 合成而不是打包 mp3，就是出于这个考虑。
- **数据文件只增字段不删字段**，保证老版本数据能被新版本读。
  新增字段必须带 `#[serde(default)]`，并补一条"只有必填字段的老 JSON 能解析"的测试。
- **Rust 与 CSS 之间有少量刻意的耦合**（例如 `BALL_DIAMETER` 必须等于 `.ball` 的宽度），
  这类地方两边都写了醒目注释，改一处要改两处。
- **新写的纯逻辑要顺手写测试**：判定的分支、边界、幂等性。
  但如果只是"加一个界面元素"这类一眼能看出对错的东西，不必强求。
- **测试里不要硬编码与"今天"相关的日期**，否则换个时区跑就会变成"昨天"。
  用远期固定日期，并在注释里写明为什么。
- 提交前跑一遍 `npm run check` 和 `cd src-tauri && cargo test`，
  再跑 `npm run test:dst` 确认夏令时断言也是绿的。
